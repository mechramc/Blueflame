## Summary

## Findings (Ordered by Severity)

### 1. Critical — Run dashboard API contract mismatch breaks core UI data flow
- Frontend expects `plan.tasks`, `agents`, and `events` in the run payload.
- API currently returns top-level `tasks` only and omits `plan`, `agents`, and `events`.
- Impact: run dashboard can render with missing/empty sections despite active runs.
- References:
  - `apps/web/app/project/[projectId]/run/[runId]/page.tsx:16`
  - `apps/api/src/routes/execution.ts:189`

### 2. Critical — Server-side RBAC/auth not enforced on mounted API routes
- API routers are mounted without mandatory auth middleware.
- Authorization endpoint accepts `userRoles` from request body, enabling role spoofing.
- Impact: privilege escalation and unauthorized plan authorization risk.
- References:
  - `apps/api/src/index.ts:46`
  - `apps/api/src/routes/authorize.ts:17`

### 3. High — Frontend auth scaffolding exists but is not wired into app runtime
- `AuthProvider` is not mounted in root layout.
- Middleware currently does not block unauthenticated access.
- Impact: auth behavior is effectively soft/optional in current UI shell.
- References:
  - `apps/web/app/layout.tsx:29`
  - `apps/web/middleware.ts:37`

### 4. High — Compliance and Chargeback pages are demo-data only
- Both pages are hardcoded to local `DEMO_ENTRIES` datasets.
- No corresponding backend API routes are mounted for these views.
- Impact: enterprise dashboards are non-operational for real project data.
- References:
  - `apps/web/app/compliance/page.tsx:52`
  - `apps/web/app/chargeback/page.tsx:21`
  - `apps/api/src/index.ts:46`

### 5. High — Demo seed does not create run/plan/budget state needed by dashboard
- Home links to fixed run (`demo-run-1`), but seed endpoint populates conversation/spec/failures/remediation only.
- Impact: demo run dashboard path can open without required execution state.
- References:
  - `apps/web/app/page.tsx:7`
  - `apps/web/app/page.tsx:96`
  - `apps/api/src/routes/demo-seed.ts:44`

### 6. Medium — Navigation does not expose enterprise pages
- Main nav includes Projects/Spec/Run/Failures only.
- `/compliance` and `/chargeback` are not discoverable from primary navigation.
- Impact: implemented pages are hidden from normal user flow.
- References:
  - `apps/web/components/layout/NavHeader.tsx:28`

### 7. Medium — Documentation/status inconsistencies
- README badges/claims are stale versus current checkpoint and licensing files.
- Impact: external reliability/trust issue for reviewers and judges.
- References:
  - `README.md:6`
  - `README.md:8`
  - `CHECKPOINT.md:19`
  - `LICENSE:1`

## Recommended Next Actions
1. Fix execution route response shape to match dashboard contract (`plan`, `agents`, `events`) or update frontend contract.
2. Enforce `authenticate` + `requireRole` at route boundaries; remove trust in client-provided `userRoles`.
3. Wire `AuthProvider` in layout and make middleware/API checks authoritative.
4. Replace demo datasets in `/compliance` and `/chargeback` with real API-backed data and add backend routes.
5. Extend demo seed to initialize run/plan/budget objects for `demo-run-1`.
6. Add nav links for enterprise pages.
7. Reconcile README claims (tests/license/status) with current state.
